#  Ubuntu发布安全修复程序，修复Linux内核关键漏洞，该漏洞允许远程代码执行  
原创 ZM
                    ZM  暗镜   2026-11-04 22:00  
  
Ubuntu 已发布针对 CVE-2026-98432 的修复程序，该漏洞是 Linux 内核在 IPv4 TCP 连接处理方面的一个严重缺陷。其 CVSS 3.1 评分为 9.8，可能导致远程代码执行。  
  
该漏洞是 tcp_v4_syn_recv_sock() 函数中的释放后使用漏洞。该函数将 ireq->ireq_opt 的所有权传递给子套接字时，并未复制该对象。如果另一个 CPU 处理了重传的 SYN 包，它可以在子套接字的选项被释放期间构建 SYNACK 包。由于内核不再持有请求套接字的监听器锁，因此没有任何东西可以阻止这种竞争条件。如果直接使用 kfree()，则会在 ip_options_build() 中留下一个悬空指针。上游修复方案在 inet_sock_destruct() 和 tcp_v4_reqsk_destructor() 中改用 kfree_rcu()。IPv6 不受第一个问题的影响。  
  
该漏洞源于与最近内核缺陷（例如SCTPhantom 释放后使用）中出现的内存生命周期错误同一类问题，其中过时的引用导致对已释放对象的访问。Ubuntu 表示Anthropic 生成的漏洞利用程序尚未公开。据报道，该程序利用了多路径 TCP (MPTCP) 技术，但该漏洞并非 MPTCP 特有。目前尚未发现其他利用该漏洞的程序。  
  
运行 `uname -r` 查看正在运行的内核。运行 `dpkg -l 'linux-image*' | grep ^ii` 列出已安装的内核软件包。将两者与上表进行比较。  
  
要应用这些修复，请按照 Ubuntu 的说明启用 `-proposed` 软件包目录。默认情况下，`-proposed` 目录中的软件包不会被升级，因此您必须使用 `apt install -t <release>-proposed` 命令显式安装它们。安装完成后，请重启系统。  
  
Canonical 表示，这种方式适合自行运行验收测试的团队。它使他们能够比完整的认证周期更快地完成测试，完整的认证周期涵盖超过 2000 台经过认证的服务器和设备。这符合 Canonical 新的内核发布策略。根据该策略，SRU 周期缩短至两周，内核每周发布一次。
